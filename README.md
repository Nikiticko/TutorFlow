# TutorFlow — Telegram Mini App

Учёт учеников, проведённых уроков и оплат по [ТЗ](./ТЗ.md). Vue 3 + Vite, локальный Node.js backend и PostgreSQL. Новая база изначально пустая; старые демоданные и localStorage не используются и не переносятся.

## Локальный запуск

Нужны Node.js 22.12+ и Docker Desktop с запущенным Docker Engine.

```sh
npm ci
npm run db:up
```

В одном терминале запустите API (схема БД создаётся автоматически):

```sh
DATABASE_URL=postgresql://tutorflow@127.0.0.1:5432/tutorflow DEV_AUTH=1 npm run server
```

Во втором терминале:

```sh
npm run dev
```

Откройте **http://localhost:5173**. Локальный режим создаёт отдельного преподавателя `local-dev`, без демонстрационных учеников. Сессия хранится в HttpOnly cookie, данные — в PostgreSQL. Перезапуск приложения не удаляет данные.

Дополнительно можно самостоятельно настроить `.env` по `.env.example`. Не публикуйте его и не передавайте токен бота во frontend. Переменные из командной строки имеют приоритет. `.env` не требуется для приведённых выше команд.

- API слушает только `127.0.0.1:3001`; Vite проксирует `/api`.
- Для другого адреса frontend задайте точный `APP_ORIGIN` (по умолчанию `http://localhost:5173`).
- PostgreSQL доступна на `127.0.0.1:5432`, volume `tutorflow_pg` сохраняет данные.
- Compose предназначен только для локальной разработки: соединения с локальной БД не требуют пароля. Не используйте эту конфигурацию на публичном сервере.
- Остановка frontend/API: `Ctrl+C`. Остановка БД без удаления данных: `npm run db:stop`.

## Возможности

- Ученики: название, заметки, вычисляемый баланс; ручного поля баланса нет.
- Уроки: дата, время и необязательная обратная связь; редактирование и удаление через меню ⋮. Записываются уже проведённые уроки, в том числе задним числом.
- Оплаты: сумма, USD/EUR, количество уроков и дата. Редактирование и удаление пересчитывают баланс; отрицательный баланс разрешён.
- Истории ученика: по 7 уроков и оплат на странице. Общая история: по 15 уроков, новые сверху.
- Free: 3 ученика и 10 уроков в неделю. Premium: 100 учеников и 200 уроков. Сервер проверяет лимиты, включая одновременные запросы. Покупка подписки отложена по ТЗ; клиент не может менять тариф.
- Корзина: восстановление в течение 30 дней, подтверждение окончательного удаления и очистки. Ученики в корзине занимают места; их уроки остаются в лимитах и статистике до окончательного удаления.
- Очистка просроченной корзины: при старте API, затем каждую минуту, а также при чтении/изменении аккаунта. При выключенном сервере очистка выполнится после запуска. Связанные записи удаляются каскадно.
- Статистика: текущие и прошлые недели, месяцы и годы; круговая диаграмма по ученикам и столбчатые диаграммы уроков/оплат.
- Конвертация оплат по последнему опубликованному курсу [Frankfurter](https://frankfurter.dev/), кэш до часа, дата курса отображается. Округление отмечается `≈`, конвертация — `↔`. При ошибке курса статистика уроков остаётся доступной, суммы оплат не подменяются нулями.

## Время

При первом входе сохраняется часовой пояс устройства (IANA). Его можно изменить в настройках. Уроки хранятся как UTC-моменты и отображаются в поясе аккаунта; недели начинаются в понедельник 00:00, включая недели с переводом часов. При двукратном местном времени осенью нужно выбрать смещение UTC; несуществующее время весной отклоняется.

Оплата хранит календарную дату, выбранную пользователем. По умолчанию это текущая дата в поясе аккаунта. Смена пояса не меняет уже введённые календарные даты оплат. В статистике оплат учитываются фактически полученные суммы, а не стоимость проведённых уроков.

## Telegram

Для реального входа задайте на сервере `BOT_TOKEN`, `DEV_AUTH=0` и `APP_ORIGIN` с точным публичным HTTPS-адресом Mini App. Проксируйте `/api` на локальный backend; frontend и API должны быть доступны через один origin. Локальный режим нельзя использовать через публичный туннель.

Frontend передаёт `Telegram.WebApp.initData` серверу. Сервер проверяет HMAC-SHA256 по [алгоритму Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app) и давность (до часа), затем выдаёт сессию на 7 дней. Доступ к данным привязан к проверенному Telegram ID. Для HTTPS cookie получает флаг Secure; POST-запросы проверяют Origin. Telegram Premium и тариф приложения — разные вещи.

В BotFather настройте Main Mini App и/или Menu Button на HTTPS-адрес приложения. Telegram требует публичный HTTPS; один localhost на телефоне недоступен. Поддерживаются тема, кнопка «Назад» и безопасные отступы клиента.

`npm run build` создаёт frontend в `dist/`. Его публикация сама по себе не запускает API и БД. Для статического размещения нужен обратный прокси `/api`; `vite preview` не заменяет production backend.

## Проверки

```sh
npm test
npm run build
TEST_DATABASE_URL=postgresql://tutorflow@127.0.0.1:5432/tutorflow npm run test:integration
```

Без `TEST_DATABASE_URL` интеграционный тест пропускается. С ним тесты создают отдельную случайную схему, проверяют настоящий PostgreSQL и HTTP API, затем удаляют только эту тестовую схему. Рабочие таблицы приложения не очищаются.

Проверяются расчёт баланса, лимиты обоих тарифов, конкурентные записи, изоляция аккаунтов, перенос уроков, корзина и каскадное удаление, Telegram-подписи/сессии, CSRF, часовые пояса/DST, периоды, конвертация и пагинация.
